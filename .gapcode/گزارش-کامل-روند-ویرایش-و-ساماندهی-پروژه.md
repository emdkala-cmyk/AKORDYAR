## فاز EventBindings

**وضعیت:** تکمیل شد.

### تغییرات انجام‌شده

- ساختار IIFE قبلی `EventBindings` به کلاس مستقل تبدیل شد.
- وابستگی‌های رفتاری از طریق constructor دریافت می‌شوند و ماژول دیگر مستقیماً به توابع global در `app.js` وابسته نیست.
- ثبت رویدادهای transport، navigation و دو handler اصلی keyboard در متد `init()` متمرکز شد.
- متد `destroy()` برای حذف listenerهای ثبت‌شده و جلوگیری از نشت رویدادها اضافه شد.
- handlerهای اصلی keyboard در `app.js` به توابع نام‌دار تبدیل و برای ثبت به `EventBindings` تزریق شدند.
- نمونه‌سازی `EventBindings` در `app.js` انجام می‌شود و هر دو ترتیب بارگذاری اسکریپت‌ها پشتیبانی می‌شود.
- از ثبت چندباره listenerها و اجرای دوگانه دکمهٔ play در event delegation جلوگیری شد.

### اعتبارسنجی

- `node --check js/app.js`
- `node --check js/core/EventBindings.js`
- `git diff --check -- js/app.js js/core/EventBindings.js`

## فاز مهاجرت inline handlerهای رابط کاربری

**وضعیت:** مرحلهٔ transport، navigation و quick search تکمیل شد.

در این مرحله ۲۸ inline event attribute شامل `onclick`، `oninput` و `onchange` از سه گروه کنترل‌های transport، آیتم‌های navigation و پنل quick search در `Akordyar.html` حذف شد. ساختار DOM و کلاس‌های CSS حفظ شدند و فقط markerهای `data-event-group`، `data-action` و `data-command` برای اتصال declarative افزوده شدند. متدهای `bindTransportControls()`، `bindNavItems()` و `bindQuickSearchPanel()` در `js/core/EventBindings.js` با event delegation روی container واقعی هر بخش تکمیل شدند و `ACTION_FUNCTIONS` در `js/app.js` بدون بازنویسی منطق توابع مقصد گسترش یافت. همچنین initialization تا آماده‌شدن کامل DOM محافظت شد تا پنل quick search که بعد از scriptها در HTML قرار دارد نیز به‌درستی bind شود. این تغییر در راستای مهاجرت تدریجی inline handlerها، کاهش وابستگی HTML به توابع global و حفظ رفتار و پایداری فعلی برنامه انجام شد.

### Inventory مهاجرت

- transport: هشت رویداد click
- navigation: دوازده رویداد click
- quick search: سه رویداد click، یک رویداد input و چهار رویداد change

### اعتبارسنجی

- syntax هر دو فایل JavaScript با `node --check`
- نبود inline handler در محدوده‌های هدف
- تطابق ۱۶ command و ۸ transport action با registry
- تست مستقل delegation برای transport، navigation، quick search و `destroy()`
- `git diff --check` برای سه فایل فنی

## فاز Safe Extraction موتور مترونوم

**وضعیت:** اتصال اولیه و bridge سازگار تکمیل شد؛ استخراج کامل هنوز انجام نشده است.

فایل `js/core/MetronomeEngine.js` در workspace موجود نبود و در مسیر طبیعی ماژول‌های core ایجاد شد. مسئولیت تشخیص عبور playhead به ضرب جدید و محاسبه accent به این موتور خالص منتقل شد. `app.js` همچنان مالک stateهای قدیمی `metroActive`، `metroTimer` و `metroBeat`، تولید صدای `playClick()`، count-in، transport و فراخوانی داخل حلقهٔ اصلی `tick()` است. توابع `startMetronome()`، `stopMetronome()` و `checkMetronomeTick()` به یک bridge حداقلی متصل شدند و مسیر محاسبه legacy در صورت نبود ماژول یا dependencyهای آن حفظ شده است.

### فایل‌ها و دلیل تغییر

- `js/core/MetronomeEngine.js`: موتور خالص و مستقل برای start/stop و تولید beat event
- `js/app.js`: ساخت adapter و delegation تدریجی بدون حذف state یا منطق صوتی قدیمی
- `Akordyar.html`: attach ماژول بعد از `Meter.js` و قبل از `app.js`
- `js/tests/metronome-engine.test.js`: تست سبک Node برای سکوت در حالت stop، عدم تکرار ضرب، accent و مترهای ترکیبی

### اعتبارسنجی

- syntax فایل‌های JavaScript با `node --check`
- تست مستقل `node js/tests/metronome-engine.test.js`
- تست برابری با فرمول legacy برای ۸ میزان‌نما و ۴ BPM
- حفظ fallback قدیمی در `checkMetronomeTick()`
- بدون تغییر در `tick()`، playback، Arranger، count-in، `playClick()` یا منطق DOM

### موارد باز برای مراحل بعدی

- لکنت مترونوم هنگام zoom/scroll همچنان open issue است؛ این مرحله scheduler را تغییر نداده است.
- انتقال تولید صدای `playClick()` به dependency صوتی مستقل
- طراحی look-ahead scheduling خارج از RAF پس از تثبیت bridge
- انتقال تدریجی count-in بدون تغییر رفتار transport
- حذف stateهای legacy فقط پس از characterization و جایگزین کامل
