مستندات فنی کامل آکوردیار

این مستند معماری، ساختار فایلها، مدل داده، موتور صوتی، و تمام زیرسیستمهای آکوردیار را با جزئیات شرح میدهد. مخاطب: توسعهدهنده.

۱. نمای کلی

آکوردیار اپلیکیشن ویرایشگر آکورد/شعر فارسی + DAW چندترکی است که بهصورت دسکتاپ (Electron) و وب (Node.js) اجرا میشود.

دوگانگی میزبانی

همان کد در Electron و وب کار میکند با تشخیص isElectron و استفاده از window.electronAPI بهجای دسترسی مستقیم fs.

امنیت الکترون

contextIsolation: true + preload با whitelist کانالهای IPC. استاندارد امنیتی مناسب.

معماری Performance v2

جداسازی منطق اجرا/نمایش از مدل داده با performanceBridge.js و SongDocumentModel.

بدون فریم‌ورک

Vanilla JS با $() (getElementById) و رندر دستی DOM. سبک ولی مقیاسپذیری محدود.

۴. مدل داده

مدل مرکزی: edCur

آهنگ فعلی در متغیر سراسری edCur نگهداری میشود:

edCur = {
  id, artist, title, key, keyMode, tempo, timeSignature, genre,
  lyrics: [{ name, text }],        // خطوط شعر
  chords: [{ lineIndex, charIndex, name, anchorType }],  // آکوردها
  syncTimes: [],                  // زمان سینک هر خط
  chordVersions: [{name, chords}],  activeChordVersion: 0,
  styles: { tSize, tColor, tFont, tBold, align, cSize, cColor, cFont, highlightEffect },
  lineColors: [],
  editorLocked, viewStyles,
  _dawTracks: [...],  _dawClips: [...],  _dawSections: [...],  _dawLoop: {},
  _embeddedAudio: { bufferKey: {format, data} },
  _audioPaths: [{bufferKey, filePath, fileName}]
}

شیء DAW

DAW = {
  tracks: [{ id, name, icon, type, muted, solo, vol, pan, transpose, locked }],
  clips:  [{ id, type:'audio'|'chord', trackId, name, start, duration, offset, sourceDuration, color, bufferKey, _peaks, waveUrl, _embedded, _originalBlob }],
  sections: [{ id, trackId, label, start, duration, color }],
  playhead, isPlaying, isScrubbing, pxPerSecond, laneHeight, timelineDuration,
  audioCtx, masterGain, voices, bufferCache, waveCache, loopEnabled, loopA, loopB,
  isRecording, recStartTime, recPeaks, recLaneId, ...  // ضبط
}

ماندگاری

  • localStorage: آهنگ فعلی، تنظیمات، میانبرها، نقشههای MIDI، آرنگرها.
  • IndexedDB: آرشیو آهنگها + blobهای صوتی + dirHandle.
  • فایل (الکترون): پوشه Audio/ پروژه برای فایلهای کپیشده.

Undo/Redo

undoStack با serializeState() / applyState(). state شامل tracks/clips/sections/edCur. بعد از undo/redo، waveformها از bufferCache بازسازی میشوند.

۵. موتور صوتی (Web Audio)

گراف سیگنال

BufferSource → voiceGain(per-clip) → track._pannerNode → track._gainNode → masterGain → destination

هر ترک صوتی دو نود پایدار دارد: _pannerNode (StereoPanner) و _gainNode (Gain). هنگام پخش، هر کلیپ یک BufferSource و یک Gain موقت میسازد که به tr._pannerNode وصل میشود.

توابع کلیدی

  • ensureAudioCtx(): ساخت/resume DAW.audioCtx و masterGain.
  • scheduleAllFromPlayhead(): برنامهریزی پخش همه کلیپها از موقع پلیهد.
  • stopAllVoices(): توقف همه BufferSourceهای فعال.
  • updateTrackMix(trackId): اعمال vol/pan/mute/solo روی نودهای ترک.
  • decodeFileToBuffer(file): decodeAudioData برای ساخت AudioBuffer.
  • peaksFromBuffer(buffer, 2000): استخراج آرایه peak برای waveform.
  • drawWaveToCanvas(peaks, w, h) → refreshClipWaveImage(clip): رندر waveform به dataURL.

Transpose

با source.playbackRate.value = Math.pow(2, semitones/12) پیادهسازی شده (بدون تغییر pitch- preserving — سرعت هم عوض میشود).

تاریخچه باگ pan: نسخه قدیمی voiceGain را به tr._gainNode وصل میکرد (باپس کردن panner). اصلاح شد: اکنون به tr._pannerNode وصل میشود تا بالانس واقعاً اثر کند.

۶. الکترون و IPC

فرآیند اصلی (electron-main.js)

  • سرور Express را در فرآیند اصلی (یا child) روی پورت ۳۰۰۰ اجرا میکند.
  • BrowserWindow با contextIsolation:true و preload.js.
  • منوی اپلیکیشن (File/Edit/View) با accelerator و ارسال IPC به renderer.
  • هندلرهای IPC: audio:read-file, audio:copy-to-project, fs:check-exists, project:save-with-audio, dialog:show-message-box, getPathForFile (webUtils).

preload.js

contextBridge.exposeInMainWorld('electronAPI', {...}) با whitelist کانالها. isElectron: true برای تشخیص محیط.

تشخیص محیط

const isElectron = !!(window.electronAPI && window.electronAPI.isElectron) || process.versions.electron;

fs و path در renderer با contextIsolation در دسترس نیستند؛ بهجایش از window.electronAPI استفاده میشود.

asar: false در build → فایلها از کامپایل محافظت نمیشوند. برای محصول تجاری ملاحظه کنید.

۷. ویرایشگر آکورد و شعر

ساختار DOM

  • #editor: contenteditable RTL، خطوط .eline.
  • #chordLayer: لایه مطلق روی editor، آکوردها با position:absolute.

سیستم لنگر آکورد (Anchor)

هر آکورد با سه نوع لنگر:

  • LineStart (charIndex ≤ 0)
  • OnCharacter (charIndex بین ۱ و طول)
  • LineEnd (charIndex ≥ طول)

کلیدهای جهت در حالت انتخاب آکورد، charIndex را با توجه به RTL جابهجا میکنند.

چند نسخه آکورد

chordVersions[] روی Chord Line. activeChordVersion نسخه فعال را مشخص میکند. switchChordVersion(), addChordVersion(), renameChordVersion().

حالات آکوردگذاری

  • لایرس: نقطه‌گذاری روی متن با موس. کورد لاین: نقطه‌گذاری با آهنگ روی تایملاین (کلید ۰).
  • ترتیبی (Sequential): با Enter ویرایشگر برای موقع فعلی باز میشود.
  • ضبط آکورد MIDI: isRecordingChords با ورودی MIDI کلیپ آکورد میسازد.

ویرایشگر آکورد (Modal)

انتخاب root (A-G با #/b)، type (maj/min/m/7/dim/aug/sus/add)، tension (9/11/13/b9/...)، bass (/G). ۴ ستون با chord-item ها.

۸. موتور DAW / تایملاین

رندر

  • renderTracks(): هدر ترک + لاین. هر ترک با نوع chord/section/audio/rec رندر متفاوت.
  • renderClips(): حذف همه .clip و بازسازی از DAW.clips. waveform با refreshClipWaveImage.
  • renderRuler(): رولر با Canvas (میزان/ضرب/ساب‌بیت) + برچسبها.
  • updatePlayheadUI(): موقعیت #main-playhead و #playhead-hit.
  • renderAll(): ترکیب همه + edRenderClMarkers().

ترنسپورت

  • startTransport(): requestAnimationFrame(tick) با حلقه پخش. پلیهد = originTime + (now - originPerf)/1000.
  • pauseTransport(): توقف + stopAllVoices(). اگر در حال ضبط باشد، endRec() صدا زده میشود.
  • stopTransport(): پاز + پلیهد=0 + auto-advance ارنجر.
  • seekTransport(t): جابهجایی. حلقه A-B در tick بررسی میشود (حین ضبط غیرفعال).

تعامل

  • onClipMouseDown: drag/resize/select کلیپ. onDocMouseMove/Up تکمیل درگ.
  • beginScrub: کلیک روی رولر/پلیهد → seek. حین ضبط مسدود است.
  • Marquee selection، cross-lane drag، Alt+drag کپی.
  • Snap-to-grid با snapTime(). Split با Shift+کلیک.

میانبرها

سیستم SHORTCUT_DEFAULTS + SHORTCUTS (localStorage) + matchShortcut(e, id). MIDI Learn با MIDI_MAPS.

۹. ضبط صدا

جریان

getUserMedia({audio:true})
  → createMediaStreamSource → AnalyserNode → MediaStreamDestination → MediaRecorder
  → chunks[] → Blob → decodeAudioData → AudioBuffer → clip
  • ensureRecLane(): ترک «Rec» را تضمین میکند (با نودهای صوتی).
  • startRec(): گرفتن میکروفن، ساخت گراف، شروع MediaRecorder + transport.
  • tickRecWave() (rAF): خواندن getFloatTimeDomainData، push peak، renderLiveRecWave().
  • renderLiveRecWave(): رسم Canvas waveform قرمز رشدی روی لاین.
  • endRec(): توقف رکوردر → onstop → finishRec(blob).
  • finishRec(blob): decode → ساخت clip با _embedded + _originalBlob → ذخیره در IndexedDB.
حین ضبط: پلیهد با موس غیرقابل جابهجایی (beginScrub مسدود). حلقه غیرفعال. میانبر R toggle.

۱۰. میکسر

  • toggleMixer(): باز/بست پنجره #mixerPanel (fixed). موقعیت در _mixerPos ذخیره میشود.
  • renderMixer(): ساخت کانال برای هر ترک صوتی. هر کانال: نام (input)، M/S، Volume، Balance.
  • تغییر نام از میکسر → tr.name + renderTracks() (دوطرفه).
  • تغییر نام از لاین → renderMixer() اگر باز است.
  • Volume: direction:ltr (چپ→راست زیاد). Balance: دابلکلیک → ریست وسط.
  • همه کنترلها updateTrackMix() را صدا میزنند → اثر فوری روی صدا.

۱۱. آرشیو

  • IndexedDB با objectStore songs. edGetAllSongs() / edSetAllSongs().
  • تصاویر خوانندهها در localStorage (arch_artist_img_) با fallback به فایلهای assets/artists/.
  • اسلایدر خوانندهها با ۲۸ خواننده پیشفرض + جستجو.
  • منوی زمینه (کلیک راست): ویرایش، کپی، حذف، export.
  • ایمپورت اتومات از لامینور: server.js با jsdom اسکرپ میکند. parseDeclaredSongCount، extractLaminorSongLinks.

۱۲. ارنجر / اجرای زنده

  • arrangers[] در localStorage (arrangers_v1). هر ارنجر: setlist + تنظیمات.
  • حالت اجرا: arrPerformActive، آهنگ بعدی با loadArrSong(idx) خودکار لود میشود.
  • پنل اجرا (#arrPerfOverlay) قابل کشیدن با arrPerfDragHandle.
  • پاپ‌آپ اجرا (Singer/Player View) با F9. حالت تمرکز F10.
  • Performance Architecture v2: performanceBridge.js با rebuildSongDocumentFromEdCur().

۱۳. تنظیمات و تم

  • APP_SETTINGS در localStorage (ed_app_settings).
  • تمها: THEMES با ۵ preset (dark/midnight/ocean/sunset/forest) که CSS variables را override میکنند.
  • رنگ سفارشی: applyAccent(color) روی --accent-teal و --accent-cyan-glow.
  • دستگاه خروجی: navigator.mediaDevices.enumerateDevices() + AudioContext.setSinkId().
  • Toggleها: مترونوم، برگشت به ابتدا، قفل اندازه — به توابع موجود (toggleMetronome، toggleSizeLock) وصل.
  • پنجره تنظیمات #settingsModal با کلاس mv-window (قابل کشیدن).

پنجرههای قابل کشیدن

initMovableWindows(): delegated mousedown روی h3/h4/.mv-head/.shortcut-panel-header → drag پنل. شامل: ویرایشگر آکورد، آیکون پیکر، نت آهنگ، شرتکات، تنظیمات. ارنجر سیستم خودکار دارد.

۱۴. پارسر آکورد

منطق parse آکورد پراکنده در app.js است و parser-test.js (۶۱۵ خط) آن را تست میکند.

ساختار آکورد

chord = {
  root: 'C'|'C#'|'Db'|...|'B',     // ۱۲ نت با #/b
  type: 'None'|'maj'|'min'|'m'|'7'|'dim'|'aug'|'sus2'|'sus4'|'add9'|...,
  tension: ''|'9'|'11'|'13'|'b9'|'#9'|'#11'|'b13',
  bass: 'None'|'C'|'C#'|...        // /G bass note
}

مراحل parse

  • تشخیص root: A-G با # یا b.
  • تشخیص type: m/min (مینور)، dim، aug، sus، add، عدد (۷/۹/۱۱/۱۳).
  • تشخیص tension: b9، #9، #11، b13.
  • تشخیص bass: /G در انتقال.
  • Auto-fix: حذف ستاره * و برعکس کردن ترتیب آکورد.
پارسر کامل به نظر میرسد ولی در برابر قالببندی نامنظم شکنندگی دارد (مثلاً هنوز * نیاز به cleanup دارد).

خلاصه

آکوردیار پروژهی بالغ و کارآمدی است با امکانات غنی (DAW + ویرایشگر آکورد + آرشیو + اجرا + ضبط + میکسر). نقاط قوت اصلی: یکپارچگی، دوزبانه، Web Audio واقعی، امنیت الکترون مناسب.

چالش اصلی: مقیاسپذیری نگهداری به دلیل تمرکز در یک فایل غول‌پیکر و وضعیت پراکنده. برای رشد آینده، شکستن ماژولها و متمرکزسازی state ضروری است.
